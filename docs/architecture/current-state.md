## Immediate Quality Direction

The next low-risk increments are:

1. Continue real Go package movement from `domain/agent` / `domain/artifacts` / `domain/jobs` / `domain/models` / `domain/simulation` / `domain/workers` and the first platform auth/config/contracts/HTTP/metrics packages toward additional domain packages, handler/package surface reduction, and later public constructor signature narrowing while preserving MemoryStore/PostgresStore coverage.

3. Expand `check-deps` only after existing code is brought into compliance with each new rule.
4. Add focused browser coverage for the feature-query backed Compute routes before deeper route/component decomposition when that coverage unlocks a concrete route split.
5. Expand scenario-level smoke evidence beyond the current material-balance job path to browser, packaged Desktop worker/installer, security, release, and golden scenario lanes.
6. Promote Desktop package/release artifact evidence to hosted CI before treating the Desktop offline golden scenario as complete.
7. Connect Water Ontology policies to real authorization/data-scope/audit implementation only after the runtime security model is explicit and test-backed.
8. Revisit Go/Python/Rust generated contract and ontology types only after package boundaries and Desktop package runtime validation are stable.
9. Continue production security with real issuer/JWKS or deeper service-token secret integration, remaining object/mutation data-scope filtering, all-mutation audit coverage, and hosted security evidence.
