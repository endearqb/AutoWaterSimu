## 22:55 - UDM Network v2 一级菜单与节点视觉复用 [L2]

- 用户目标：将 UDM Network v2 提升为一级菜单，补齐出水端，并在不复用 legacy FlowCanvas 的前提下复用节点选择器、颜色和装饰条节点组件。
- 涉及目录：`frontend/src/components/Common/`、`frontend/src/components/Flow/`、`frontend/src/features/udm-v2/`、`frontend/tests/`、`scripts/`、`.ai/decisions/`、`tasks/`。
- 修改内容：将 `/udm-v2` 移出 FlowingFlow 子菜单；为共享 `NodePalette` 增加可选 drag MIME/value/tint；V2 节点面板复用该选择器；增加 influent/effluent boundary 预设；V2 node shell 复用 `GlassNodeContainer` 与 glass colors 并保留左侧装饰条；source/sink 在合同序列化中往返；边界检查增加三个精确 UI 白名单。
- 修改原因：V2 需要与 legacy UDM 保持一致的节点选择和视觉语言，但仍需隔离画布、状态、端口规则和序列化逻辑。
- 本次已消除的不确定性：确认原出水端缺失源于 palette 只有通用 Boundary 且 factory 默认 source；确认合同允许用既有 boundary + source/sink node type 表达，无需新增 schema 枚举；确认可复用项均为纯展示原语。
- 本次采用的关键假设：“出水端”表示 effluent sink boundary，只有 hydraulic inlet；其余 V2 专用节点继续保留在选择器中。
- 剩余不确定性：无。
- 影响范围 / 风险控制方式：未复用 FlowCanvas、legacy store、legacy node behavior 或 service；未新增依赖、未升级合同；boundary script 只放行三个精确 import。
- 验证证据：`cd frontend; npm run typecheck` → exit 0；`npm run test:unit -- --run` → 17 files / 52 tests passed（保留既有 Chakra/jsdom CSS stderr）；`npm run check:udm-v2-boundary` → passed；Chromium `udm-v2-route.smoke.spec.ts` → 2 passed；Chromium `udm-v2-ui-parity.spec.ts` → 4 passed且四视口无横向溢出；scoped Biome → 88 files checked / no errors；`git diff --check` → exit 0；README contract check 仍仅被根 `README.md` / `README_zh.md` 既有的 `./release-notes.md` 断链阻塞。
- 是否更新 README：是，更新 legacy Flow、UDM-v2、palette 和 nodes 目录契约。
- 是否需要新增或更新架构决策（.ai/decisions/）：是，更新 ADR 0028，允许三个 presentation-only UI 原语的精确白名单复用。
